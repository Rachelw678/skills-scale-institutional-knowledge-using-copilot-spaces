# OctoAcme Project Management Documentation

Welcome to the OctoAcme project management process library. This directory contains a structured set of guides for how OctoAcme runs projects from idea through delivery, release, and retrospective.

## Overview of OctoAcme project management

OctoAcme uses a simple, repeatable project lifecycle built around a few core principles:

- Customer-first: prioritize customer value and usability.
- Iterative delivery: break work into small, testable increments.
- Clear ownership: define roles, responsibilities, and accountability.
- Data-informed decisions: measure outcomes and adjust based on evidence.
- Psychological safety: encourage feedback, learning, and continuous improvement.

The project lifecycle follows five main phases:

1. Initiation — validate the problem, align stakeholders, and make a go/no-go decision.
2. Planning — define scope, milestones, backlog, and dependencies.
3. Execution — build, test, review, and track progress toward delivery.
4. Release — deploy, verify, communicate, and monitor outcomes.
5. Close & Retrospective — capture lessons learned and improve the process.

## Core roles

Projects rely on cross-functional collaboration. Common roles include:

- Project Manager (PM): coordinates schedules, risk, communication, and delivery flow.
- Product Manager (PdM): defines outcomes, prioritizes the roadmap, and measures success.
- Developers: implement features and maintain quality through testing and review.
- QA/Testing: validate acceptance criteria and release readiness.
- Stakeholders: provide input, approve milestones, and support business alignment.

## Key artifacts

Across the lifecycle, teams use the following artifacts to keep work visible and aligned:

- Project charter / one-pager
- Roadmap and release plan
- Sprint or iteration backlog
- Acceptance criteria and definition of done
- Risk register
- Project board workflow
- Retrospective notes and action items

## Communication cadence

OctoAcme teams maintain regular communication to keep stakeholders aligned:

- Daily standups for progress and blockers
- Weekly cross-functional sync between PM and product lead
- Sprint or milestone reviews and demos
- Monthly stakeholder updates
- Ad-hoc escalation for business-impacting risks or dependencies
